## API
`validateTrafficExchangeWithSourceHealth(request,response,{activeRequest,evaluatedAt,sources})` invokes unchanged `validateTrafficExchange` first and unchanged `evaluateTrafficSourceHealth`. Returns `{valid,errors,warnings,sourceHealth,sourceDiagnostics,sourceIds}`. Structural and echo errors are preserved; source gate can only add failures. Invalid health envelope returns structured `SOURCE_HEALTH_INVALID_INPUT`. No ambient clock, defaults, I/O, source filtering or response mutation.

Citations are audited in caller order at actual response paths: each candidate `routingBase/measured/historical/forecast.source` when explicitly present (including nonselected candidates), `incidents[].source`, `selected.source`, and every `provenance[]` item (including independence evidence). Every cited ID must resolve to exactly one valid, technically usable source-health entry with the identical nonblank declared licenseRef. Missing, duplicate, invalid, stale, no-data, denied, unknown, unlicensed or license mismatch blocks the entire exchange. Bad unreferenced providers remain visible in `sourceHealth` diagnostics but do not block otherwise valid exchange. Warnings such as RECENT_FAILURES or LATE_UPDATE do not independently block fresh eligible providers. Source licenses are caller declarations, **not legally verified**. No passability, coverage, truth or truck-safe claim.
