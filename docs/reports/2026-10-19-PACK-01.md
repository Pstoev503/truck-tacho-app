## Как работи проверката

Стъпката в CI:

```
docker run --rm -i --network none top10eu-server python - /app/web < scripts/check-packaged-web.py
```

Скриптът се подава през stdin на Python-а **в образа** и проверява `/app/web` в образа, не checkout-а на runner-а. Не се отварят портове, не се стартират API или база, няма мрежа (`--network none`) и тайни.

Checker-ът:
1. Изисква `planner.html`, `ui/map-planner.mjs` и `ui/map-planner.css`.
2. Тръгва от `planner.html` и следва рекурсивно:
   - `<script src>`, `<link href>`, `<img src>`;
   - ES `import … from`, `export … from`, `import '…'` и `import('…')` с литерал;
   - CSS `url()` и `@import`.
3. Всяка относителна референция трябва да е четим файл в `WEB_ROOT`.
   - Външни (`http:`, `https:`, `data:`, `//`, `#`) се пропускат.
   - Bare module specifier (например `'leaflet'`) е грешка.
   - Път извън `WEB_ROOT` е грешка.
4. При проблем изписва всички проблеми и дава exit 1. Не брои файлове по фиксиран брой: нов import (например `planner-initial-state.mjs` от UI-02) влиза в проверката автоматично.

## Реални проверки

### Локално (Docker 29.8.2, Python 3.13.16)

`pip install` в образа не минава през proxy-то на тази среда, защото контейнерът не вярва на неговия CA. TLS проверката не е изключвана. За локалния build е използван временен вариант на същия `Dockerfile` в scratchpad (не е комитнат). Той добавя само два реда преди `RUN pip install`: `COPY --from=proxyca ca-bundle.crt /tmp/proxy-ca.crt` и `ENV PIP_CERT=/tmp/proxy-ca.crt`. Всички `COPY` към `/app/web` са същите като в комитнатия файл. Меродавното доказателство е CI run-ът по-долу.

## Ограничения

- Проверката доказва наличие и разрешимост на файловете в образа. **Не** е HTTP/браузърен тест (MIME типове, `StaticFiles` поведение, изпълнение на модулите) и не е security проверка.
- Импортите се разпознават с регулярни изрази, а не с пълен JS parser. Импорти, генерирани динамично от низове, не се проследяват.
- `ui/map-planner.test.mjs` също се копира в образа, защото се копира цялата `ui/`. Не е изпълним в браузъра, а само статичен файл.
- Локалният build е с добавен proxy CA (описан по-горе). CI build-ът е без промени.
