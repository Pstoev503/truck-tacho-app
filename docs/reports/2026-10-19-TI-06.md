## Public API and boundary
Existing `validateTrafficExchangeWithSourceHealth(request,response,{activeRequest,evaluatedAt,sources,maxExchangeAgeMs})` now requires caller-supplied `maxExchangeAgeMs`, a strictly positive safe integer in **milliseconds**. No default TTL, ambient clock, coercion or IO. `evaluatedAt` is caller UTC ms, nonnegative safe integer, shared with source health. The existing TI-02 contract validates ISO `response.evaluatedAt`; temporal gate additionally requires parsed UTC ms to be nonnegative safe integer.

The added `exchangeHealth` is `{state,reason,ageMs,maxExchangeAgeMs,responseAtMs}`. States: `fresh` for `0 <= ageMs < maxExchangeAgeMs`; `stale` for `ageMs >= maxExchangeAgeMs` **including equality**; `future` when response time is later than caller clock; `invalid-input` for malformed clock/response timestamp or missing/invalid explicit TTL. Errors are appended as `{code,path}`: `EXCHANGE_INVALID_MAX_AGE` at `options.maxExchangeAgeMs`, `EXCHANGE_INVALID_EVALUATED_AT` at `options.evaluatedAt`, `EXCHANGE_INVALID_RESPONSE_TIME`, `EXCHANGE_FUTURE_RESPONSE`, `EXCHANGE_STALE_RESPONSE` at `response.evaluatedAt`. Difference-based age avoids unsafe TTL addition. Original contract errors and sourceHealth diagnostics remain. A future route departure is not an invalid response clock.

No response mutation, ETA modification, transport inference or license verification. This is an **explicit caller technical policy**, not a legal/operational universal TTL and not a truck-safe guarantee.
