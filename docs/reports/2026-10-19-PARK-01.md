## API

```js
import { evaluateParkingCandidates, MAX_PARKING_CANDIDATES } from './parking-candidates.js';
const result = evaluateParkingCandidates(request); // pure, синхронна
```

### Вход

| Поле | Тип и правило |
|---|---|
| `requestId`, `routeRevision`, `inputRevision` | непразни string |
| `geometry` | масив `{lat, lon}` както в GEO-01. Проверява се с `indexRoute`: поне 2 точки, ненулева дължина, \|lat\| < 85, без antimeridian/антиподални сегменти |
| `evaluatedAt` | цяло число ≥ 0, UTC ms. Модулът не чете часовника |
| `window` | `{minOffsetM, maxOffsetM, maxLateralDistanceM}`: крайни числа ≥ 0 в метри; `minOffsetM ≤ maxOffsetM ≤` дължината на маршрута. Офсетите са **разстояние по маршрута** от началото му |
| `parkingCandidates` | масив, 0–1000 записа (`MAX_PARKING_CANDIDATES`) |

Непознати полета на заявката или прозореца са грешка (`UNKNOWN_FIELD`).

Всеки запис в `parkingCandidates`:

| Поле | Правило |
|---|---|
| `id` | непразен string, уникален в заявката |
| `location` | `{lat, lon}`: крайни числа, \|lat\| ≤ 90, \|lon\| ≤ 180 |
| `sourceId` | непразен string или липсва (`undefined`/`null`) |
| `observedAt`, `expiresAt` | цели числа ≥ 0 (UTC ms) или липсват |
| `truckAccess` | `'allowed'`, `'prohibited'` или `'unknown'`; ако липсва, се приема `'unknown'` |
| `availability` | `'available'`, `'full'` или `'unknown'`; ако липсва, се приема `'unknown'` |

Непознато поле в запис прави записа `invalid`. Достъпът и наличността са **декларирани от източника**; модулът не ги удостоверява.

### Изход

```js
{
  requestId, routeRevision, inputRevision,  // echo; null, ако съответното не е валиден string
  status: 'evaluated' | 'invalid-input',
  errors: [{ code, field, details }],       // само при invalid-input; иначе []
  evaluatedAt, routeLengthM,                 // само при evaluated
  window: { minOffsetM, maxOffsetM, maxLateralDistanceM },
  duplicateIds: [...],
  summary: { total, geometricCandidates, needsVerification, excluded, invalid },
  results: [ /* по един за всеки входен запис, сортирани */ ],
  candidateIds: [...],          // id на geometric-candidate, в реда на results
  needsVerificationIds: [...],
  selectedParkingId: null, accessVerified: false, reservationConfirmed: false,
  limitations: [ /* 5 текста */ ]
}
```

Всеки елемент в `results`:

```js
{
  id,                // null, ако id е невалиден
  inputIndex,        // позиция във входа
  projectionStatus,  // 'matched' | 'ambiguous' | 'off-route' | null (invalid)
  routeOffsetM, lateralDistanceM,  // метри; null при ambiguous/off-route/invalid, никога 0 вместо null
  withinWindow,      // true/false при matched, иначе null
  evidenceState,     // 'fresh' | 'unknown' | 'expired' | null (invalid)
  truckAccess, availability,       // декларираното (или 'unknown'); null при invalid
  disposition,       // 'geometric-candidate' | 'needs-verification' | 'excluded' | 'invalid'
  reasons: [...],    // машинни кодове, детерминиран ред
  accessVerified: false, reservationConfirmed: false
}
```

Кодове на top-level грешки:
- `INVALID_REQUEST`, `UNKNOWN_FIELD`, `INVALID_STRING`;
- `INVALID_TIME`;
- `ROUTE_GEOMETRY_REQUIRED`, `INVALID_ROUTE_GEOMETRY` (`details` е съобщението на GEO-01);
- `INVALID_WINDOW`, `WINDOW_OUTSIDE_ROUTE`;
- `INVALID_CANDIDATES`, `TOO_MANY_CANDIDATES`.

Всички грешки се връщат заедно.

## Поведение

### Проекция

- `projectToRoute(index, location, { maxDistanceM: window.maxLateralDistanceM })` се вика **по целия маршрут**, после прозорецът се проверява по върнатия `routeOffsetM`.
- Ако прозорецът се подаде на `projectToRoute` като `minOffsetM`/`maxOffsetM`, паркинг далеч от прозореца би се проектирал на ръба му и изглеждал близо. Mutation проверка: този вариант проваля 5 теста.
- `ambiguous` (отклонение, самопресичане) остава `ambiguous` и `excluded`, с `null` позиция. Модулът не избира страна.
  - Ограничение: паркинг до двете страни на отклонение, от които само едната е в прозореца, също е `ambiguous`/`excluded`. Консервативно е и не се отгатва.
- `off-route` означава извън коридора (`lateralDistanceM > maxLateralDistanceM`); границата е включена.
- Точка с \|lat\| ≥ 85 е `invalid` с `unsupported-location` (ограничение на GEO-01).

### Свежест

Проверките са в този ред:

1. `observedAt > evaluatedAt` → `invalid` (`observed-in-future`). `expiresAt < observedAt` → `invalid` (`expires-before-observed`).
2. Нечислови, дробни, отрицателни, `NaN` или `Infinity` времена → `invalid` (`invalid-observedAt` / `invalid-expiresAt`).
3. `evaluatedAt >= expiresAt` → `expired`.
4. Липсва `sourceId`, `observedAt` или `expiresAt` → `unknown` (`source-unknown`, `observed-at-unknown`, `expires-at-unknown`). Няма default TTL и не се приема, че липсващото е свежо.
5. Иначе → `fresh`.

### Disposition

| disposition | Условие |
|---|---|
| `invalid` | malformed запис, невалидно време или дублиран `id` (всички записи с този id) |
| `excluded` | `off-route`, `ambiguous`, извън прозореца, `expired`, `truckAccess:'prohibited'` или `availability:'full'`. Prohibited и full изключват дори при неизвестна свежест: декларирана забрана не се пренебрегва |
| `needs-verification` | matched и в прозореца, не е изключен, но свежестта, достъпът или наличността е `unknown` |
| `geometric-candidate` | само matched + в прозореца + `fresh` + `allowed` + `available` |

`reasons` изброява всички приложими причини в този ред:
1. геометрия: `outside-window`, `ambiguous-route-position` или `outside-corridor`;
2. свежест;
3. `truck-access-prohibited` или `truck-access-unknown`;
4. `reported-full` или `availability-unknown`.

Валидните записи не изчезват заради невалидни.

Дори `geometric-candidate` не доказва:
- реален подход, посока или страна на пътя, вход или клас на камиона;
- пристигане навреме, законна почивка или място при пристигане.

Модулът не избира, не резервира и не мести почивките на planner.

### Детерминиран ред

`results` е сортиран по:
1. disposition: `geometric-candidate`, `needs-verification`, `excluded`, `invalid`;
2. `routeOffsetM` възходящо, `null` накрая;
3. `lateralDistanceM`;
4. `id` (code-unit сравнение, `null` накрая);
5. `inputIndex`.

Разбъркан вход дава същия ред (тест).

### Чистота

- Няма `Date.now`, HTTP, DB, файлова система, feed, OSM или тайни. Тестът подменя `Date.now` с функция, която хвърля грешка.
- Входът не се мутира: тестът подава deep-frozen вход и сравнява със snapshot.
- Изходът се състои от нови обекти. `limitations` е споделен frozen масив.

## Ограничения

- Само геометрия и декларирани данни. Не проверява подход, посока на движение, страна на пътя, вход, ограничения за камиони, време на пристигане, правилата за почивка или наличност при пристигане. Не е truck-safe.
- Проекцията е по голям кръг (GEO-01): \|lat\| < 85, без пресичане на antimeridian, без антиподални сегменти. Толерансът за ambiguous е по подразбиране на GEO-01 (5 м).
- Липсващ `truckAccess`/`availability` се третира като `'unknown'`, а `null` за `sourceId`/времена като липсващо. Това е избор на договора, описан тук.
- Модулът още не е свързан с planner или UI; това е отделна задача.
