# Граници на собственост и координация

Това е план за отделяне на паралелната работа, а не разрешение за промяна на съответните runtime файлове в този PR. Тази промяна е само документация.

## Планирани пакети

| Собственик / пакет | Планиран обхват | Състояние в тази промяна |
| --- | --- | --- |
| Codex — планировчик и нормативен одит | `engine/plan.js`, `engine/plan.test.js`, `docs/planner-contract-v1.md`, `docs/planner-rules.md` и DATEX одит | Отделна работа. Тези локални файлове не са налични за преглед в cloud checkout; не се променят тук. |
| Следващ Copilot пакет — интерфейс и маршрутни адаптери | `boss.html`, `index.html`, `engine/route.js`, `engine/route.test.js` и UI/route API адаптери | Не започва в този PR. Съществуващият `shef` код е инвентаризиран, но не се променя. |
| Координиран общ пакет | `engine/tacho-rules.js`, `engine/tacho-rules.test.js`, `engine/activity-log.js`, `engine/activity-log.test.js`, синхронизационните файлове, manifests/dependencies и `.github/workflows/` | Заключени за несъгласувани промени. Съгласувайте отделен пакет и тестов план преди редакция. |

„Заключени“ означава без промени от паралелен пакет, докато няма изрично съгласуване. Това не променя собствеността на проекта и не е Git защита на файловете.

## Правила за граници

1. Един пакет има един отговорен собственик и предварително посочени файлове.
2. Промяна извън изброения обхват изисква координация преди редакция; общите броячи, дневник, синхронизация, зависимости и workflows не се променят инцидентно.
3. Тестовете се променят заедно със съответния пакет, без да се използват като доказателство за изпълнение, докато няма отчет от реално изпълнена команда или CI run.
4. Нормативен/протоколен одит е отделно доказателствено задължение. Не превръщайте непроверена нормативна референция в твърдение за API спецификация.
5. Отчетът посочва SHA, засегнати пътища, извършени проверки и оставащи зависимости. Не се приписва локален код или тестов резултат на cloud checkout без сравнение.

## Последователност

1. Codex завършва собствен planner/rules/DATEX пакет и предоставя diff, доказателства и тестов отчет.
2. След това се съгласува Copilot пакетът за страниците, маршрутите и адаптерите; приема се само след проверка спрямо договорения planner API.
3. Общите модули и инфраструктура остават без промяна или се отделят в изрично одобрен координиран пакет.
4. Физическото преместване на runtime файлове е отделна миграция, с план и rollback по [REPOSITORY-LAYOUT.md](REPOSITORY-LAYOUT.md).
