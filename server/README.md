# Сървър (профили, шефско меню, маршрути)

Сървърът пази данните на фирмата и ги показва на собственика. Телефонът на шофьора брои сам и работи и без сървъра. Когато е свързан с фирмата, на всяка минута праща дневника на дейностите си.

Python (FastAPI) и PostgreSQL. Може да сервира и самото приложение: `index.html` за шофьора и `boss.html` за шефа.

## Какво има

| | |
| --- | --- |
| **Фирма и собственик** | Регистрация и вход с имейл и парола (`/api/owner/register`, `/api/owner/login`). Паролата се пази като scrypt отпечатък. |
| **Шофьори** | Собственикът добавя шофьор и получава еднократен код за 7 дни (`XXXX-XXXX`) и връзка. Шофьорът отваря връзката и телефонът се свързва сам. Един шофьор има един телефон: нов код изключва стария телефон. |
| **Синхронизация** | `PUT /api/sync`. Телефонът праща записите от последните 3 дни и кратък образ на броячите. Сървърът заменя записите от началото на прозореца нататък и пази по-старите за историята. Пращат се и смените от отчета. |
| **Жив отчет** | Шефското меню взима дневника и смята броячите в браузъра със същия код като в кабината (`engine/tacho-rules.js`). |
| **Местоположение** | Само ако шофьорът го разреши в менюто. Пази се само последната точка и само докато работи (не по време на почивка). |
| **Маршрути** | Шефът чертае точки на картата и праща маршрута на шофьор. Шофьорът го получава при следващата синхронизация и го отваря в Google Maps или като GPX. Без сървър маршрутът тръгва като връзка. |
| **Календар и история** | По шофьор и седмица: каране и работа по дни, лента на денонощието, смени, нарушения с член от регламента. |

Защита: всеки вход е отделен токен (пази се само sha256). Опитите за вход и за код са ограничени. Собственикът вижда само своята фирма. Шофьорът може само да отбележи маршрут като видян или минат.

## Пускане при теб (за проба)

```bash
# PostgreSQL с база taho и потребител taho/taho
cd server
pip install -r requirements.txt
DATABASE_URL=postgresql+psycopg://taho:taho@127.0.0.1:5432/taho WEB_ROOT=.. uvicorn app.main:app --port 8000
```

После отвори `http://127.0.0.1:8000/boss.html` и натисни „Нова фирма“.

Тестове: `pip install -r requirements-dev.txt`, после `TEST_DATABASE_URL=postgresql+psycopg://taho:taho@127.0.0.1:5432/taho_test pytest -q`. В GitHub се пускат сами при всяко качване (`.github/workflows/tests.yml`).

## Пускане наживо (сървър в ЕС)

Нужни са две неща, които трябва да направиш ти, защото изискват профил и плащане:

1. **Машина в ЕС.** Например VPS с Ubuntu при доставчик с център в Германия или Финландия. За пилота стига най-малката машина (2 GB RAM).
2. **Домейн.** Насочи A запис (например `api.твоятдомейн.bg`) към IP адреса на машината.

После на машината:

```bash
# Docker: https://docs.docker.com/engine/install/ubuntu/
git clone https://github.com/Pstoev503/truck-tacho-app.git
cd truck-tacho-app/server/deploy
cp .env.example .env        # попълни DOMAIN, DB_PASSWORD (openssl rand -hex 32), REGISTRATION_CODE
docker compose up -d
```

Caddy взима HTTPS сертификат сам. Готово е, когато `https://ДОМЕЙН/api/health` отговори с `{"ok":true}`.

Шефското меню е на `https://ДОМЕЙН/boss.html`, а приложението на шофьора — на `https://ДОМЕЙН/`. Най-добре е шофьорите да ползват приложението от домейна на сървъра, а не от GitHub Pages: на собствения домейн входът е само за това приложение. Ако шофьорите вече имат приложението от друго място, сложи адреса му в шефското меню (⚙ → „Адрес на приложението за шофьорите“) — поканите и маршрутите ще водят там.

Обновяване: `git pull && docker compose up -d --build`.

## GDPR

- Данните са в ЕС, в твоята база.
- Местоположението е изключено, докато шофьорът не го пусне сам.
- Дневникът на дейностите е същият, който тахографът така или иначе записва.
- Преди пилота трябва да има кратко уведомление за шофьорите: какво се пази, защо и колко време. Това не е правен съвет — за договора с фирмите говори с юрист.
